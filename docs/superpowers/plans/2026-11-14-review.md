> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `packages/review`, the headless review core that turns an `ingest-segment` `CandidateSet` into em-v1 `Sample`s in a `GlyphStore` (write-through, replayable decision log, coverage report), plus a thin FastAPI + canvas UI over it, proven by an end-to-end test that builds a font from the reviewed store with `font_gen.run.run_build`.

**Architecture:** One `hwfont-schema` precursor (`GlyphStore.remove_sample`/`get_sample`). Then a new hatchling package whose modules form `inputs → session (stats) → decisions (pure ops) → normalize (em-v1 materialisation) → store_sync (the only store writer) → coverage`, with I/O confined to `inputs.py`, `decisions.load_log/save_log`, `store_sync.py` and `run.py`. `app.py` is a FastAPI factory calling the same functions; `static/` is one HTML page and one JS file with no build step.

**Tech Stack:** Python 3.12+ (repo venv 3.14), pydantic v2 (`hwfont-schema`), Pillow 13, numpy 2.5, FastAPI 0.162 + uvicorn 0.54 (extra `ui`), httpx 0.28 (dev, `TestClient`), font-gen (dev, end-to-end only), pytest 9.

**Spec:** [docs/superpowers/specs/2026-11-14-review-design.md](../specs/2026-11-14-review-design.md)

- Frame: page px are y-down; em is y-up; `s = 1 / region.bbox.h`; `y_em = (region.baseline_y − y_px)·s`; `x_em = (x_px − origin_x_px)·s`, `origin_x_px = ink.xmin − LSB_px`; `LSB_px = ½·(ink.xmin − left.xmax)`, `RSB_px = ½·(right.xmin − ink.xmax)`; `bbox.x = LSB`; `advance = LSB + bbox.w + RSB`. Crop origin is `(int(bbox.x), int(bbox.y))` (truncation, as `ingest_segment.segment._crop_png`).
- Sample id `f"{session_id}-{candidate.id}"`; `Metrics.baseline = 0.0` always; `review_status = accepted` always (rejected candidates are removed, never stored); `Sample.created_at = decision.updated_at` (so replay reproduces write-through exactly).
- Unit order, neighbour identity and neighbour ink extents come from the **original** candidates (boxes, labels, strokes), never from the log; a neighbour named by `Context` counts only when the adjacent unit's original label agrees (`adjacent.label[-1] == left_neighbor`, `adjacent.label[0] == right_neighbor`), else that side uses the session median and the sample is flagged `neighbor_mismatch`.
- One `review.json` per candidate directory; its `session_id` must equal the session's (`--session`, default the sidecar stem) or loading is a `ReviewError` naming both.
- Decision log file: `review.json` in the candidate directory, written via `<path>.tmp` + `os.replace`.
- Commits: stage explicit paths only (never `git add -A` / `git add .`; an untracked `.env` exists), conventional message, last line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Work on branch `feat/review`.

## Review Focus

Five input classes the spec implies but its own test list never exercises; each is pinned by a test in the owning task.

1. **A candidate whose stroke file is listed but empty of points inside its own box** (ingest assigned a straddling stroke by the 50 % rule): `candidate_extent` must come from the stroke points as stored, not re-filtered by the box, so the extent never collapses to `None` while strokes exist (Task 5).
2. **Two candidates in one region with identical boxes** (vision duplicated a unit): `unit_order` must be deterministic (tie by candidate id) and the half-gap between them is `0`, not an exception (Task 6).
3. **A region whose first unit is a punctuation mark with `left_neighbor=None`** and a wide gap to the next word: the missing-neighbour side takes the session median, never the measured gap to a non-neighbour (Task 7).
4. **Relabel of an accepted candidate to a label with a different kind** (`a` → `th`): the store must hold exactly one sample with the new kind and no orphan sidecar (Task 8).
5. **A `review.json` written by a newer set** (decision for an unknown candidate id) and a set that grew since the log was written: the first is a `ReviewError`, the second yields default decisions for the new ids (Task 4).
